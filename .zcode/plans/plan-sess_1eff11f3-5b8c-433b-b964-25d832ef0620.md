## 目标

开盘时（9:25-9:30）用 Wireshark 抓同花顺 PC 客户端的 8901+9601 全流量，搞清两件事：
1. **开盘批量请求 7000 个个股**：客户端启动时如何一次性拉全市场代码表 + 行情快照（subreal×8 订阅 + 特殊 CodeList + init 启动序列）
2. **盘中实时推送**：9601 pushrealorder 异动推送的频率、负载、代码分布

抓的是**被动监听 hexin.exe 的真实流量**，不需要 THSClient 账号。

## 一、新建 `tests/capture_market_open.py`（二合一抓包脚本）

完全沿用 `capture_hexin_start.py` / `capture_stock_list.py` 的约定，做它们的自然兄弟脚本。

### 常量（关键：用用户指定的新 Wireshark 路径 + 正确的 magic）
```python
WS = r"D:\软件\Wireshark-4.4.7-x64-with-Npcap-1.50-Portable\Wireshark\App\Wireshark"
```

### 沿用标准件（与现有脚本逐字一致）
- 两行头 `#!/usr/bin/env python` + `# -*- coding: utf-8 -*-`，无 `from __future__`
- docstring：操作步骤（退出同花顺→跑脚本→启动同花顺登录→等开盘→结束）+ `产物：captures_live/market_open.pcap`
- `list_interfaces()`：`tshark -D` + `encoding="gbk", errors="replace"` + 正则 `(\d+)\.\s+(\S+)\s+\((.+?)\)`
- `pick_interface()`：交互选网卡，WLAN 默认带 `← 推荐` 标记
- `capture(iface, duration)`：`dumpcap -i <n> -f "tcp port 8901 or tcp port 9601" -w PCAP -a duration:N`，`timeout=duration+15`，KeyboardInterrupt/TimeoutExpired 处理，打印 `抓包完成：{PCAP} ({size:,} bytes)`
- `_tshark(y_filter, fields)`：标准查询 helper
- `_split_frames(payload)`：split on MAGIC + 去 8B ASCII 长度头
- `main()`：argparse（`--duration` 默认 180、`--iface`），banner + 选网卡 + 抓包 + 分析，`raise SystemExit(main())`

### 分析阶段 `analyze()`——两段报告

打印风格沿用 `【1】【2】` 编号 + `=`*70 分隔 + `★/✗/✓/⚠` 标记 + 中文标签 + `collections.Counter`。

**【0】连接概览**
- 8901/9601 各连了哪些服务器 IP（用 MARKET_HOSTS/REALORDER 服务器清单标注）
- SYN 时间线（前 20），看启动时连了几条连接、是否并发

**A 段：开盘批量请求（7000 股）**
- **【A1】启动序列帧统计**：把客户端发出的帧（dstport 8901/9601）按类型分类计数，**过滤掉心跳**（8901 心跳 hdr[7:11]==`12 00 03 00` 或文本含 `tsi0=`/`tc=`；9601 心跳为 5 字节 `09 ?? ?? ?? 07`）。类别：
  - `method=subreal`（8901 订阅，market=URS/UCT/UNX/UME/UGF/UNS）
  - `method=subrealorder`（9601 订阅，action=add/del）
  - `CodeList=` 请求——细分：含 `DataType=199112`（代码表翻页）/ 含 `1B0987`（触发码）/ 含 `PushField=`（快照）/ 普通行情
  - `C-Version=E029` + `StockLinkVer=`（init 帧）
  - `method=qurealorder`（历史查询）
- **【A2】批量请求结构**：挑 2-3 个代表性请求，打印完整文本字段——DataType 真值、CodeList 编码（`market(codes,)` 带尾逗号）、SortBegin/SortCount。重点回答"是不是一次性请求拿全量 vs 翻页"。
- **【A3】响应规模**：统计服务器返回的 hd3.1/hd1.0 响应，解析 dc（记录数）；标出 dc≈7400 的全市场代码表大帧（一次性返回），以及 SortTotal。回答"7000 股是一次返回还是分批"。
- **【A4】连接模型**：按 `(dst_ip, stream)` 分组批量请求，看走几条连接、是否同连接复用。

**B 段：盘中实时推送**
- **【B1】pushrealorder 帧统计**：数量、总字节、帧大小 min/avg/max、时间跨度、频率（帧/分钟）。
- **【B2】异动代码分布**：Format A（`\x21([036]\d{5})`）+ Format B（`\x2d.{1,2}([036]\d{5})`）提取的代码 Counter，top 15。
- **【B3】9601 订阅确认**：subrealorder 订阅了哪些 market（16/32/151/48）。

**【结论】**：汇总——批量请求是翻页还是一次性、全市场代码是否一次返回、推送频率量级。
