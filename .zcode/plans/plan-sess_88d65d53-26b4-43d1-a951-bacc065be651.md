## 复刻同花顺的测速选 IP 机制

抓包铁证：同花顺并发 TCP 握手测多个 IP 延迟（SYN→SYN-ACK），选最快的 login。
- 122.9.115.201 = 28ms（最快）
- 其他 = 54-74ms
- 114.115.236.165 = 超时（剔除）

thspypc 当前盲取前 7 个，经常选到慢 IP。

## 改动：新增 `_probe_fastest_hosts` + connect 时先测速

**文件**：`src/thspypc/client.py`

### 新增 `_probe_fastest_hosts(hosts, top_n=7, timeout=1.0)`
- 并发对每个 IP 发 TCP 连接到 8901（`socket.create_connection`），测握手往返时间
- 连上立即关闭（不发 login，不触发 -1）
- 按延迟排序，返回最快的 top_n 个 IP
- 超时/失败的 IP 剔除
- 测速整体耗时 ≈ timeout（1s，并发），70 个 IP 并发测完 ~1s

### 修改 `_do_tcp_login_raw`
- `hosts = resolve_market_hosts(...)` 后，调 `self._probe_fastest_hosts(hosts)` 测速排序
- `batch = fastest[:7]`（用测速结果，而非盲取前 7 个）
- 测速日志：打印最快的几个 IP + 延迟
- 测速失败（全部超时）时回退到原逻辑（盲取前 7 个），保证可用性

### 关键点
- **纯 TCP 握手测速，不发 login** → 不触发 -1（-1 是 login 帧内容触发的，TCP 连接不触发）
- **连接立即关闭** → 不占用服务器资源，不留残留 session
- **测速结果缓存**（可选）：同进程内多次 connect 复用测速结果，避免重复测。但首版不缓存（每次 connect 测一次，1s 开销可接受）
- 超时 1s 足够：抓包显示最快 28ms，最慢 74ms，1s 能区分；真正不可达的 IP（如 114.115.236.165）会被剔除

## 不做的事
- 不解析/连 8601（thspypc 用 8901 做 login + 行情查询，8601 是同花顺的独立行情数据端口，thspypc 不需要）
- 不缓存测速结果到磁盘（IP 延迟会变，每次 connect 测一次更准；首版保持简单）

## 验证
- 测速日志应显示 122.9.115.201 等快 IP（28ms 级）排在前面
- connect 总耗时：HTTP 鉴权 0.6s + 测速 1s + login 0.1s + init 0.3s ≈ 2s
- 比当前"盲选慢 IP + 白等"（46s）快一个数量级
