# 逆向 qustocklink 拿 A 股列表

## 背景与目标

Windows PC 客户端用 `method=qustocklink`（8901端口，纯文本帧）+ `StockLinkVer` 字段做股票列表的增量同步。已抓到请求结构，但响应里只有期货/期权板块（Stock_64/68/69），**没有 A 股板块（Stock_16_A_SO/Stock_32_A_SO）**——因为增量同步只发变化的部分。

目标：构造 qustocklink 请求，**用 `ConfigVer=0`（或空 StockLinkVer）骗服务器发全量 A 股列表**，确认 A 股的 token 格式，然后写解析器。

## 已确认的事实（无需再调研）

1. **请求格式**（纯文本帧）：`\x09` + GBK 文本
   ```
   instid={instance}
   method=qustocklink
   c-version=E029.60.20.0031
   stocklinkver=^bConfigInfo^B^r^nConfigVer^e{ver}^r^n^bStock_16_A_SO^B^r^nConfigVer^e{ver}^r^n...
   ```
   控制字节：`^b`=0x02(块开始), `^B`=0x01(节开始), `^r`=0x12, `^n`=0x0e(行结束), `^e`=0x05(键值分隔), `^c`=0x03(列分隔)

2. **响应格式**（`rettype=ini`）：同样的控制字节结构
   ```
   ^bStock_16_A_SO^B^nCheckSum^eXXXX^nConfigVer^eYYYY^n
   {节标题}^e{token1}^c{token2}^c...^n
   ```
   - 期货板块的节标题是合约代码（`ag2609`、`CF2703`）
   - token 是 `市场码:6字符base64`（如 `69:GYo6BR`）或明文（`UZCO:SR2611MSC4700`）

3. **28 个 Stock 配置项**已知（StockLinkVer 里列出的），A 股相关：
   - `Stock_16_A_SO` = 沪市A股，`Stock_32_A_SO` = 深市A股
   - `Stock_16_Z_SO`/`Stock_32_Z_SO` = 沪深指数，`Stock_64_C_SO` = 北交所
   - `Stock_144_P_SC` = 创业板

## 实施步骤（分两阶段）

### 阶段 1：实测探针（先确认 A 股格式，再决定解析器怎么写）

**新增 `tests/probe_qustocklink.py`** —— 构造请求实测脚本：

1. 用 thspypc 连接 8901（复用现有 connect）
2. 构造 qustocklink 请求，**只带 Stock_16_A_SO（沪市A股）一个板块**，`ConfigVer=0`（表示本地无缓存，骗全量）
3. 发请求，收响应，**完整 dump 到文件**（captures_live/qustocklink_resp.bin）
4. 终端打印响应的前 2000 字节（控制字节可视化）+ 统计：
   - 有没有 `Stock_16_A_SO` 块？
   - 节标题是 6 位明文代码（`600519`）还是别的？
   - token 格式是 `16:XXXXXX` 还是明文？
   - 总共多少个代码？

**为什么先只带 1 个板块**：全量 28 个板块响应可能几十 MB，先拿沪市 A 股确认格式，避免数据量爆炸难分析。

**ConfigVer=0 的风险**：服务器可能拒绝（要求有效版本号）、或返回空（认为没更新）、或真的发全量。如果失败，备选策略：
- 用抓包里的真实 ConfigVer（`202607170840`）但只带 A 股板块，看是否单独返回
- 试 `ConfigVer=1`（极旧版本）
- 试不带 stocklinkver 字段（空请求）

### 阶段 2：解析器（确认格式后写，不在本次计划硬编码）

根据阶段 1 的实测结果，新增 `protocol.py`：
- `build_qustocklink_query(stocks, config_vers)` —— 构造请求
- `parse_qustocklink_response(body)` —— 解析响应，返回 `{板块: [(标题, token), ...]}`
- `client.stock_list(market="16A")` —— 高层封装，返回 A 股代码列表

**这一步依赖阶段 1 结果**，先不在计划里固化细节。

## 验证方式
跑 `py tests/probe_qustocklink.py`，看它能否拿到 `Stock_16_A_SO` 的响应。三种可能结果：
1. **成功**（返回 A 股列表）→ 进入阶段 2 写解析器
2. **ConfigVer=0 被拒** → 试备选策略（真实版本号/空字段）
3. **完全不通** → 说明 qustocklink 有额外鉴权/握手，需再抓包看 init 流程

## 风险
- **请求构造错误**：控制字节（0x02/0x01/0x0e/0x05）如果漏了或多了一个，服务器可能返回错误或超时。探针脚本会完整记录原始响应字节，便于调试。
- **响应过大**：全量 A 股可能 5000+ 条，单帧可能跨多个 TCP 包。脚本用现有的 `read_frame`（处理 FD FD FD FD 帧边界），但需注意大响应可能分多个帧。
