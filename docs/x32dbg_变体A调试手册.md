# x32dbg 攻克变体 A（name_16_16 块状编码）操作手册

> 目标：在同花顺冷启动写 `stockname_16_0.txt` 的瞬间，抓到解码后的明文缓冲区，
> 倒推解码函数地址。**不需要理解算法**，只需机械操作 3 步。
>
> 预计耗时：20~30 分钟。需要同花顺能正常登录联网。

## 为什么这样做能成

同花顺把网络收到的 `[name_16_16]` 密文段解码成明文后，会调用 `CreateFileW` 创建
`stockname_16_0.txt` 并写入。我们在 `CreateFileW` 下断、用文件名过滤，就能精确卡在
"解码刚完成、明文还在内存里"的瞬间。此时：

- **栈上**有调用链（一路 return 地址回溯，能定位是哪个函数调的写文件）
- **内存里**有刚解出的明文（`[name_16_16]\r\nConfigVer=...600000=浦发银行...`）
- 逆着调用链往上走几层，就是解码函数

## 前置准备

1. **关闭同花顺**：任务管理器确认 `hexin.exe`、`HxDataService.exe` 都结束。
2. **清空名称缓存**（关键！不清不会触发全量解码）：
   - 删掉 `C:\同花顺软件\同花顺\stockname\` 下的 `stockname_16_0.txt` 和 `stockname_16_0.base`
   - （只删 16 这两个就行，其他市场的留着无所谓）
3. **启动 x32dbg**：双击 `D:\software\x64dbg\release\x32\x32dbg.exe`

---

## 第 1 步：attach 同花顺并在写文件处下断

1. 先启动同花顺（`C:\同花顺软件\同花顺\hexin.exe`），**停在登录框先别登录**。

2. 在 x32dbg 里：菜单 `File` → `Attach`（或按 `Alt+A`），列表里选 `hexin.exe`，确定。
   attach 成功后进程会暂停。

3. 在下方命令栏输入（两个都下，最稳，不知走 A 还是 W）：
   ```
   bp CreateFileA
   bp CreateFileW
   ```
   回车。下方 Breakpoints 面板应出现两条断点。

4. 按 `F9`（或点 ▶ 运行）让同花顺恢复运行。

5. **回到同花顺登录**。登录后它开始拉数据，会反复命中 `CreateFileW` 断点。

---

## 第 2 步：用文件名过滤，只留 stockname_16

每次命中 `CreateFileW` 时，看右侧寄存器区的 **`ECX`**（this 指针无关）或直接看栈。

`CreateFileW` 的第一个参数（文件名指针）按 stdcall 在栈上 `[ESP+4]`。在命令栏输入：

```
dword [esp+4]
```

这会在内存窗口显示文件名字符串。**如果看到的不是 `stockname_16_0.txt`，按 `F9` 继续运行，
直到命中的那个文件名是 `...\stockname_16_0.txt`**（或 `stockname_16_0.base`）。

> 💡 如果嫌手动按 F9 烦，可以下**条件断点**（一次设好自动过滤）。先删掉普通断点：
> `bc` （清掉 CreateFileA/W 两个）
> 再下条件断点（只当文件名含 `stockname_16` 时断）：
> ```
> bp CreateFileA
> bpcond CreateFileA, "strstr(ascii:[esp+4], "stockname_16") != 0"
> bp CreateFileW
> bpcond CreateFileW, "strstr(wstr:[esp+4], "stockname_16") != 0"
> ```
> （x32dbg 版本若不支持 strstr 条件，就用上面的手动 F9 法，更省心）

命中 `stockname_16_0.txt` 后**先别按 F9**，进入第 3 步。

---

## 第 3 步：抓明文 + 抓调用链（3 个 dump）

此时明文刚解好、正要写盘。在命令栏依次执行以下命令，**把每条的输出截图或复制**给我：

### 3a. 调用链（最重要 —— 定位解码函数用）

```
k
```
（显示调用栈 Call Stack）。会看到一串 `返回地址`，从上往下格式类似：
```
hexin.exe.0x????????  <- 当前 CreateFileW 的调用者
hexin.exe.0x????????  <- 上一层（可能是写文件封装）
hexin.exe.0x????????  <- 再上一层 ← 解码函数很可能在这附近
...
```
**把这整列地址复制给我**。解码函数就在"写文件封装"往上的 1~3 层。

### 3b. 内存里的明文（验证解码成功）

CreateFileW 只是创建文件，明文缓冲区地址要往上找。先看调用栈最上面那个 hexin 地址
（3a 里第一个非系统地址），假设是 `0xAABBCCDD`，在命令栏：

```
dis 0xAABBCCDD
```
（跳到那段代码）。看它附近有没有 `push <某指针>` 准备传给 WriteFile 的参数。
那个指针指向的就是明文缓冲区。假设指针值是 `0x11223344`，用：

```
dump 0x11223344
```
在内存窗口应能看到类似 `[name_16_16]....ConfigVer=20260722_...600000=浦发银行...` 的明文。

**如果能找到明文**：把那段内存的前 256 字节 dump 给我（内存窗口右键 → Binary → Copy）。

### 3c.（进阶）回溯到解码函数本体

在 3a 的调用栈里，从上往下数第 2~4 个 hexin 地址，逐个用 `dis <地址>` 跳过去看。
**解码函数的特征**：函数体较长、有循环、读取输入缓冲区（密文）写入输出缓冲区（明文）。

找到疑似函数后，记下它的**入口地址**和入口处的前几行汇编（`dis` 窗口截图）。

## 第 4 步：把结果发给我

把以下任意能拿到的发我，我来分析定位解码函数：

- ✅ **3a 的调用栈地址列**（最关键，有这个就能定位）
- ✅ 3b 的明文内存 dump（验证用）
- ✅ 3c 疑似解码函数的入口地址 + 前几行汇编

拿到这些后，我会：
1. 用调用栈地址在脱壳 exe 里反查，精确定位解码函数入口
2. 反汇编该函数，搞清 ctrl 位定义 + match 字节 offset/len 编码
3. 写出纯 Python 解码器，集成进 `decode_name_frame()`

## 备选：如果 CreateFileW 命中太频繁/过滤不了

改用**代码地址断点**（需要先实测 delta）：

1. attach 后，在命令栏输入 `mod hexin.exe` 看 imagebase（假设是 `0x00400000`）。
   真实 delta = imagebase - 0x400000（脱壳 exe 的默认基址）。
   HANDOFF §10 记录的 delta 是 `-0x2a0000`，即运行时地址 = 静态 VA - 0x2a0000。

2. 在写文件处下断（静态 VA `0x167aecc`，运行时 `0x167aecc - 0x2a0000 = 0x13daecc`）：
   ```
   bp hexin.exe:0x13daecc
   ```
   （如果 imagebase 不是 0x400000，用 `0x167aecc + (imagebase-0x400000)` 重新算）

3. 这个断点只在写 stockname 文件循环时命中，不会被其他写盘干扰。命中后同第 3 步。

## 常见问题

**Q: attach 后同花顺卡死/无响应？**
A: 正常，调试器暂停了进程。按 F9 恢复运行即可。调试期间同花顺会变慢属正常。

**Q: 命中 CreateFileW 但文件名是乱码/别的？**
A: 按到 `stockname_16` 为止。同花顺启动会写大量文件（日志/配置），耐心 F9。

**Q: 调用栈里地址都是 `hexin.exe.0x...`，怎么知道哪个是解码函数？**
A: 把整列发我。我会用脱壳 exe 反查每个地址落在哪个函数里，自动判断。

**Q: 清了缓存但冷启动后 stockname_16_0.txt 没重新生成？**
A: 可能登录的账号/网络没触发全量。确认：①彻底退出同花顺再启动 ②删除后启动到登录完成
   要等 30 秒~1 分钟 ③检查 `stockname\` 目录是否又出现了 `stockname_16_0.txt`。
