# 个股历史分时「强状态省略型」codec 攻坚交接

> 状态：算法性质已确认（字段级变长省略压缩），成对 oracle 样本已定位，
> 控制字节状态机待逆向。本文档给出可执行的攻坚路径。
> 创建：2026-07-30。
> 关联：[`HISTORY_TIMELINE_VARLEN_INVESTIGATION.md`](HISTORY_TIMELINE_VARLEN_INVESTIGATION.md)
> 是更早的调研记录，本文是它的算法攻坚续篇。

## 一、问题定性：这是一种压缩算法，不是协议路由问题

### 与沪市竞价 LZ77 的关系

「强状态省略型」和沪市早盘集合竞价的 LZ77 外层压缩是**两类不同的自研压缩**，
作用于不同层，但同属「hexin 自研压缩族」：

| 维度 | 沪市竞价外层 LZ77 | 个股历史分时省略型（本文） |
|------|------------------|--------------------------|
| 作用层 | 整帧外层（`cmd=0x0a`） | hd1.0 内层记录区（每条记录） |
| 算法 | LZ77 变体（64K 哈希字典 + 滑动窗口） | **字段级前值/增量复用**（控制字节驱动） |
| 压缩对象 | 整个 hd1.0 帧的字节流 | 单条记录里的字段值 |
| 已破解 | ✅ `normalize_8901_response`（移植自 RVA `0xf74260`） | ❌ 控制字节状态机未破 |

**结论**：请求和服务器都正常，数据就在帧里。外层 LZ77 两类帧共用同一个解压函数，
已经能解；真正没破的是内层「每条记录省掉几个字节」的字段级压缩。

### 三层结构回顾

```
cmd=0x0a 外层压缩流                         ← 已破解 normalize_8901_response
  └─ hd1.0 个股子表（flag=0x0082, hs=92, fc=23）
       └─ 241 条记录，每条 23 字段（标称 92 字节）  ← 本文攻坚点
            dt1/10/13/19/22/23/54/201-204/207-210/223-230
```

## 二、铁证：变长步长（实测 2026-07-30）

对 `captures_live/history_companion_000001_000938_20260514_20260728_174530.bin`
（normalize 后 45201B）里的两张 `flag=0x0082` 表，用 bar 锚点定位行首，
测量相邻记录的物理跨度：

### 表0 = 强状态省略型
- `dc=242, flag=0x0082, hs=92, fc=23`，字段表与表1 完全相同
- 恢复 225 个锚点（应 241）
- **步长分布**：91×89 次、92×67 次、90×61 次、89×3 次 → 固定 92 仅占 30%
- 范围 89~825 —— **变长**
- 前 8 行实测（off=362 起，bar=132477534）：

  ```
  off=362  bar=132477534  stride=0    （第1条，完整）
  off=454  bar=132477535  stride=92
  off=546  bar=132477536  stride=92
  off=638  bar=132477537  stride=92
  off=730  bar=132477538  stride=92
  off=821  bar=132477539  stride=91   ← 省略从第6条开始
  off=911  bar=132477540  stride=90
  off=1002 bar=132477541  stride=91
  ```

### 表1 = 完整锚点型
- 同 `dc=242, flag=0x0082, hs=92, fc=23`
- 恢复 235 个锚点
- **步长分布**：92×220 次（94%）、90×7、184×4 → 几乎全固定 92
- `first_bar=132477534`，与表0 **完全一致** → 完美的成对 oracle 样本

### 关键推论

标称记录宽 92 字节（23 字段×4）。完整型几乎填满 92。**省略型把每条压缩到
89~91 字节**，平均省 1~3 字节。省略发生在：

1. **bar 高位省略**：`dt1`（bar_index）原本 4 字节，可能只存低 2~3 字节，
   高位靠「前一条 + 步长」隐式恢复 → 省 1~2 字节。
2. **字段值前值/增量复用**：某字段与上一条相同（或差值可预测）时不重复存，
   插入一个「控制/状态字节」标记「沿用前值」或「增量 N」→ 再省几个字节。

## 三、当前代码如何处理（安全降级）

`src/thspypc/features/history_timeline_protocol.py`：

- `flag=0x0082` 个股表只用固定 6 个核心字段
  `_HISTORY_TIMELINE_STOCK_CORE_FIELDS`（dt1/10/13/19/22/23），靠 bar 锚点定位
  （`_history_timeline_row_anchors`，:420）。
- 遇省略型时锚点能恢复约 225/241 个点，核心字段大部分精确（文档记录
  224/232 精确），但 **dt54 之后的 Level2 字段无法恢复**。
- 无法安全恢复时**严格拒绝**（返回空让上层重试），**绝不**把错位字节伪装成
  合法行情。这是正确选择——不能输出错误数据。

## 四、攻坚路径（按顺序）

### 第一步：用成对样本做逐字节 oracle 对齐（纯语料，不需逆向二进制）

这是最关键、性价比最高的一步。两张表的 `first_bar` 相同（132477534），
意味着它们是**同一日期同一只股票的两份编码**——一份完整、一份省略。

做法：
1. 把完整型（表1）的 241 条记录按固定 92 字节切分，得到每条的标准字段值。
2. 把省略型（表0）的 241 条按 bar 锚点逐条对齐到完整型同 bar 的记录。
3. 对每条省略记录，与完整记录做**逐字节 diff**：
   - 哪些字节位置一致（未省略的字段）？
   - 哪里少了字节（省略点）？省略点前后是什么内容？
   - 多出来的「控制字节」长什么样？出现在记录的哪个偏移？
4. 统计所有省略点的共同模式：是否某个固定偏移位置出现标记字节？
   标记字节的值与「省略了哪个字段」是否一一对应？

预期产出：一张「省略规则表」——控制字节值 → 省/留哪些字段、怎么恢复。

### 第二步：验证状态机假设

用第一步归纳的规则，在省略型样本上**正向重建**每条记录：
- 按规则补回 bar 高位、复用前值字段，重建出完整 92 字节。
- 与完整型 oracle 逐字段比对，要求 23 个字段全部精确匹配。
- 若有不一致，回到第一步修正规则假设。

### 第三步（可选）：二进制逆向确认状态机

若纯语料对齐无法穷尽所有省略模式（某些模式样本里没出现），再读 hexin.exe
的解码逻辑确认。参考已破解的同类压缩：
- LZ77 外层：移植自 RVA `0xf74260`（Unicorn 模拟逐字节对照，见
  `docs/handoffs/HANDOFF_SUPERORDER_20260726.md` 第十七~二十章）。
- BitRLE：移植自 RVA `0x13746d0`（决策树翻译，见 HANDOFF §1）。
- 方法论见 [`THS_REVERSE_ENGINEERING_PLAYBOOK.md`](THS_REVERSE_ENGINEERING_PLAYBOOK.md)。

省略型 codec 的解码函数 RVA 尚未定位，需先用第一步的锚点
（如 `parse_history_timeline_response` 调用栈、或 dt54 字段编号 54）
在 hexin.exe 里交叉引用找到。

### 第四步：实现 codec 并接入

- 在 `history_timeline_protocol.py` 新增省略型解码路径：
  完整型走原固定字段路径；检测到省略标记时走新 codec。
- 去掉「严格拒绝」，改为按状态机重建完整记录。
- 用四个日期（2026-05-13/14、06-30、07-23）的 241 点 thsdk oracle 逐点回归
  （thsdk 真值见 `HISTORY_TIMELINE_VARLEN_INVESTIGATION.md`「thsdk 真值」表）。

## 六、验收口径

1. 省略型样本 241 点的 23 个字段全部与完整型 oracle 精确匹配（不只是前 6 个）。
2. 四个日期的 thsdk 逐点回归通过。
3. 离线回归测试覆盖（用真实抓包帧做 fixture，同 auction 测试模式）。
4. 不再依赖实验探针的随机变体重请求（当前为收集变体用的临时手段）。

## 七、风险与备选

- **风险**：状态机可能依赖客户端持有的额外状态（如服务端推送的初始字典），
  纯请求-响应无法复现。若第一步对齐发现规则无法自洽，考虑此可能。
- **备选（务实路线）**：若逆向成本过高，把「严格拒绝」改为「返回已能安全解出的
  前 6 核心字段 + 标注 dt54+ 缺失」。这样历史分时可用，不强求 Level2 扩展字段。
  注意：dt54+ 的 Level2 字段（大单金额双线）在当日分时 `timeline`（4214）已能取
  （dt227-230），历史分时缺它不影响 PC 版核心复刻。
