# Level2 委买 / 委卖队列（7173 / 7174）

> 适用范围：**沪深 Level2**。北交所无委托队列通道（2026-09-08 抓包确认，官方
> 超级盘口页也无队列），Web 北交所页对应面板显示"无此通道"。

## 结论

2026-08-09 用历史超级盘口和客户端截图交叉验证后确认：

| period | 含义 | 请求 | 权限 |
|---|---|---|---|
| 7173 | 买一委托队列 | `DataType=10, DateTime=7173(-1-0)` | Level2 专属 |
| 7174 | 卖一委托队列 | `DataType=10, DateTime=7174(-1-0)` | Level2 专属 |

响应是 `hd1.0` 专用表：`flag=0x002A, hs=4, fc=1`，字段表只有
`dt56(0x30, 4B)`。它不是逐笔成交 7169，也不是盘中 71B 推送。

队列项的 32 位值解释如下：

```text
shares   = raw & 0x07ffffff
is_major = bool(raw & 0x08000000)
hands    = (shares + 50) // 100
```

`0x08000000` 对应客户端中带底色的“主力单”。返回窗口通常最多显示 50 笔，
`total_order_count` 才是该价位总委托笔数；`entries` 只是可见窗口，不能用其求和
代替买一/卖一总量。响应壳中的 `meta_value` 与 4096 的 dt123（买）/dt125（卖）
对齐，但当前不赋予“队列总量”语义。盘口总股数应取同一时点 4096 的 dt25（买一）
或 dt31（卖一）。

## 历史上下文

历史日期不能直接写入 7173/7174。客户端流程是：

1. 在对应市场的同一条 Level2 连接请求 `pageid=4417, period=4096(<全天区间>)`；
2. 连接保留目标交易日上下文；
3. 再发 `pageid=4417, 7173(-1-0)` / `7174(-1-0)`。

目前只确认服务端提供最近一个交易日的委托队列。更早交易日即使 4096 快照存在，
7173/7174 也可能只返回空 ACK。因此公开 API 不承诺任意历史日可用，空 ACK 被解析为
`empty=True`，不当作协议错误。

## 截图交叉验证

- `688693`（2026-08-07 涨停）：7173 返回买一 93.38、总 700 笔；可见主力项
  9900、99800、8393、5000 股，共 123093 股 = 1230.93 手、4 笔，与客户端
  “主力买单 1231 手，共 4 笔”一致。7174 为空。
- `000779`（2026-08-07 跌停）：7173 为空；7174 返回卖一 12.85、总 7756 笔，
  可见手数序列与截图逐项一致；3 个主力项合计 1258898 股 = 12588.98 手，
  与客户端“四舍五入显示 1.3 万手，共 3 笔”一致。

## API

```python
# 当前上下文，只取一侧
buy = client.order_queue("688693", "buy")

# 最近交易日历史上下文；4096 只请求一次，再取买卖两侧
queues = client.order_queues("688693", trade_date="2026-08-07")
buy, sell = queues["buy"], queues["sell"]
```

普通账号在建立 Level2 socket 之前即抛出 `CapabilityUnavailableError`。不要尝试用
普通 MAIN 连接重放请求，也不要为买卖两侧分别重新鉴权或登录服务器。

## 活网验证（2026-08-09）

生产 API 用全新进程、一次 HTTP 鉴权、单一目标市场 Level2 连接验证：

| 股票 | 买一 | 卖一 | 4096 顶栏总量 |
|---|---|---|---|
| 688693 @ 2026-08-07 | 93.38，700 笔，可见 49，主力 4 笔/1230.93 手 | 空 ACK | 买一 10698 手 |
| 000779 @ 2026-08-07 | 空 ACK | 12.85，7756 笔，可见 49，主力 3 笔/12588.98 手 | 卖一 145824 手 |

普通账号 `.env.normal` 活网鉴权后调用同一 API，在建立 L2 TCP socket 前按能力证据
拒绝，验证结果为 `PASS: standard account rejected before L2 socket login`。

验证命令见 `tests/verify_order_queue_online.py`。若某一 Passport64 在目标节点首次即
返回 `VerifyCode=-1`，连接层丢弃该票据并重新 HTTP 鉴权；不会拿已成功消费的票据
登录另一台服务器。
