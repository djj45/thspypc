## 一、你记得的「统一入口」确认

逆向 8901 时找到的 hd 家族统一入口是 **hexin.exe 的 `CHQuoteFile::parse`**：

| 项 | 值 |
|---|---|
| 反汇编虚拟地址 | `0x167c8b0`（image base `0x400000`） |
| 真实 RVA | `0x127c8b0` |
| 固定头分类/读取 | `0x136c430` |
| ABI | `thiscall parse(this, buffer, length, mode)`，被调函数 `ret 0x0c` |

`0x136c430` 识别 `hq1.`、`hq6.`、`hd1.`、`hd1.3`、`hd3.*`、`hd4.1`、`hd5.*`，
并直接读 `DWORD[+6]`、`WORD[+0xc]`、`WORD[+0xe]` 等固定头字段。出处：
`docs/plans/SH_AUCTION_X86_HARNESS_PLAN.md`。

**注意：这个分类列表里没有 `hfd1.0`。** 所以不能默认 `CHQuoteFile::parse` 会处理
hfd1.0；对照 mac dylib 有 `ParseDataHxFile` / `ParseDataHqFile` 两个入口
（`D:\code\thspy\PROTOCOL_REVERSE.md` 第七节），hfd1.0 更可能属于 HxFile 一族。

## 四、已确认事实

- hfd1.0 与 mac id=200 共享 LZ 压缩原理：代码区控制字节压缩（PC 用 `0x07`，
  mac 用 `0x01`），名称 GBK 明文，数值区变长（THS float + `01 XX YY` 去重标记思路）。
- PC 版没有 mac 的 `fe0100` 锚点和 `05800000` 尾标记，控制字节也不同，不能直接复用。
- 记录边界特征：`[末位数字 ASCII + GBK 名称]`；`pre[-1] == code[-1]` 约 85%。
- 覆盖：市场 16（沪 A）、144-151（新三板/基金/北交所）；**深市 A 股（32/33）不支持**。
- 现有语料不含数值 datatype；过去所谓「数值字段扫描」实际跨进了后续压缩记录。
  必须先另采带行情 datatype 的 HFD1 响应，再用 oracle 逐条对照或动态逆向。

### 2. 路径 A：纯语料 + mac codec 移植

把 `_parse_one_record_200` 的变长字段思路移植到 PC 0x07 变体：

1. 用名称末位数字锚点切记录边界（已有 `hfd1_0_boundaries.json`）；
2. 先用 `tests/probe_hfd1_datatypes.py` 采到包含行情 datatype 的 HFD1 对照响应；
3. 再从名称结束后用「价格 + 涨速」双字段验证定位数值区起点
   （参考 `_locate_price_200`，比单价格扫描稳）；
4. 用 list_quotes oracle（价格/涨跌幅/量/额）逐条校准字段偏移和去重标记；
5. 指数 vs 股票分别建模（数值区布局可能不同）。

### 3. 路径 B：重新拿加载映像，找 hfd1.0 解析入口

1. 任务管理器导出 hexin DMP；
2. `uv run python tests/reverse_hexin_minidump.py extract-module ...` 生成
   `hexin.loaded.bin`；
3. `uv run python tests/reverse_hexin_loaded.py ... --string hfd1.0` 找字符串；
4. 找到字符串引用后 `--xref-rva` 定位解析函数，参考
   `tests/emulate_chquote_parse.py` 的 Unicorn harness 提取纯函数；
5. 记住 playbook 的教训：先确认输入是否还在已知外层（`normalize_8901_response`），
   新抓的响应如果以 `0x0a` 开头，先 normalize 再谈记录结构。

### 4. 活网补语料时的登录规则

按 `AGENTS.md`：不要手写串行登录、不要重复 connect。hfd1.0 只有部分 host 支持
（历史实测 122.9.202.190 可用），需要低层 socket 时用
`login_socket_for_domains()`，认证材料从同一个 `get_client()` 的 AuthService 取。
