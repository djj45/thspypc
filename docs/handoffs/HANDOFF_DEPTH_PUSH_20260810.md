## 个股集合竞价三行盘口

### 外层与股票块定位

外层魔数：

```text
09 7b d0 0f 7f
```

股票块不是永远从固定绝对偏移开始。抓包中代码位置包括但不限于：

- `C=45`：普通单记录；
- `C=51` / `C=57`：分别可承载 2/3 条 delta 记录；
- `C=213`：前面带状态文本或紧凑记录的变长帧。

生产解析不再搜索这些偏移；这里仅保留为抓包定位信息。实际流程是先展开为
`hd1.0` 定长行，再按字段表和标准行偏移解析。

### 已验证字段（旧版原始单记录偏移）

| 相对位置 | 含义 |
|---|---|
| `C+6` | 昨收 |
| `C+10` | 虚拟撮合价 |
| `C+22` | 普通现价；集合竞价时为 0 |
| `C+26` / `C+30` | 买一虚拟撮合价 / 撮合量 |
| `C+34` / `C+38` | 买二缺省哨兵 / 买方未匹配量 |
| `C+50` / `C+54` | 卖一虚拟撮合价 / 撮合量 |
| `C+58` / `C+62` | 卖二缺省哨兵 / 卖方未匹配量 |
| `C+126` | 打包的未匹配方向与数量 |

`C+126` 中 `0x08000000` 表示卖方，低 27 位为数量；未置位表示买方。显式的
买二/卖二数量槽优先，打包字段用于校验和紧凑变体回退。

竞价第二行没有有效委托价，生产解析结果用 `price=None` 表示，不应伪造为撮合价。

### 成功标准

客户端请求中必须至少命中：

```text
pageid=6240
T_URL=/quote/auction/...
```

服务端响应应含 JSON 根节点 `Auction`，记录字段包括：

```text
markettime, newprice, leadprice, volume
```

其中 `newprice` 是白线，`leadprice` 是黄线。普通 `09 7b d0 0f 7f` 指数行情推送
即使发生在 09:15-09:25，也不能替代这份 Auction 序列。

`T_URL`、`/quote/auction/` 请求命中数均为 0，因此指数 Auction 必须明天重抓。
