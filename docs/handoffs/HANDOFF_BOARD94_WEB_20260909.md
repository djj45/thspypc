**分时与日K分开请求**：切分时视图发 8192+7176 一组；切日K视图才发 16384。

**表头排序行为**（排序快的原因）：
- 主力金额（592890）：**零请求本地排**——2Hz 常驻轮询让数据永远在内存；
- 竞价金额：**零请求本地排**（开盘价×量间接计算）；
- 封单额/涨速：服务端 Sort（`SortBy=265260`/`48`，Count=28/页，只回代码+值小表）。

**图表上下文**：`16(1A0002)/32(399002)` + 同款 DT 集 = 成分股加载事务的
大盘基准线（thspypc 的 `BOARD_CONSTITUENT_CONTEXT_DATATYPE_L2` 同源）。

## thspypc 侧实现（与客户端差异说明）

三条板块数据通道（分时/竞价/日K）走 6002/4181 历史页面路由，客户端走
12480 组件路由——**服务端两种形态都受理**，数据逐值一致（活网核对）。
板块日K builder：`build_board_kline_query`（DT=[1,7,8,9,11,19,13]，
`16384(-{count}-{anchor})`，ReqFuquan，复用 `parse_kline_hd3_response`）。
对齐客户端字节形态（12480+0x0153+rich16+0x4A 解析）是可选纯化项。

## 关键修复

1. **成分股名字桥接**：本地 BlockUpdate 仅 881 行业同号（90/513）；概念/
   二级行业（882/885/886）按 name_48 名称组 → 本地 A 股类别（行业/概念/
   地域）板块名精确匹配 → hex block_id 展开。进程内按自然日累积缓存
   （`_bridge_board_names`）。无法解析返回 []（前端显示暂无数据）。
2. **ST 风险警示板市场码 22**：`st_market(17→22)` 在 L2 车道路由
   （kline/timeline/depth/superorder 的 `_*_l2_role`）与 `pick_l2_market`
   原先全部拒绝 22。活网对照：`CodeList=17(600734 *ST实达)` 服务端超时、
   `22` 返回日K。已全部放行（22→沪）。WS stock-stream 入口对 0/17/33
   通用推断值重新按客户端 ST 感知规则解析。
3. **Web 层健壮性**：板块四端点 + kline/depth/history_timeline/
   stock-ready + timeline/intraday/auctions/auction/closing_auction/
   quotes_ext 全部开启 `retry_transport_once`（`_call` 的重试集合扩展到
   ProtocolError/ChannelUnavailableError/RuntimeError——覆盖 L2 预热
   socket 被服务端关闭与业务请求竞速的瞬断）；`stock_ready` 补走 `_call`
   （原先 ChannelUnavailableError 裸奔 500）；板块 timeline/constituents/
   quotes/auction 端点补 `_jsonable`（raw bytes 导致 pydantic 500）；
   502/403 加 WARNING 日志、请求内重试加 INFO 日志。
4. **成分股提速**：`board_constituents` 每行按 dt10/dt6 补算 `chg_pct`
   （通道 dt66 收盘后为 0 不可用），前端涨幅首选该值——列表到达即完整
   可排序+选中首行，砍掉 quotes_ext 二跳（~2s → ~0.5s）。
