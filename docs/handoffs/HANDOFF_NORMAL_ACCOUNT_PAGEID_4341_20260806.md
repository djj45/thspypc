# 普通账号 pageid=4341 协议发现（2026-08-06 盘中）

> 用户反馈 `probe_index_today_rawframes.py`（普通账号查指数当日分时）卡住。
> 抓包 `superorder_20260806_125600.pcap`（普通账号同花顺打开指数分时）发现：
> **普通账号的通用行情 pageid 是 4341，不是代码里写死的 9354。**

## 决定性发现

同花顺普通账号（mx_6euk93lwi）打开指数分时，请求是：

```
CodeList=16(1A0001,);
DataType=272,207,42,271,228,13,41,227,19,40,10,224,23,202,223,22,201,208,
DateTime=8192(0-0)
LackTime=0,3,0,0,0,0,0,0
pageid=4341
```

而代码 `timeline_protocol.py` 用的是：

```
TIMELINE_PAGEID = 9354        ← 错！
TIMELINE_DATATYPE = [14, 13, 19, 54, 10, 23, 15, 22, 6, 45]   ← 错！
```

**pageid 和 DataType 完全不同** → 服务端收到 9354 请求不响应 → 普通账号分时超时。

## 验证：改成 4341 立刻拿到数据

用同花顺的真实参数（pageid=4341 + DataType=272,207,...）发请求，普通账号成功收到响应：

```
响应 2769B, hd3.1 @ 72
dc=121 flag=0x006e hs=72 fc=18
字段表: dt16,207,42,15,228,13,41,227,19,40,10,224,23,202,223,22,201,208
BitRLE 解码: 121 行×72B (121 个上午分时点)
```

dc=121 = 上午 9:30-11:30 每分钟一点（午休时段查到上午数据）。

## pageid=4341 是普通账号通用行情 pageid

抓包显示 4341 不只用于分时，普通账号的**所有行情请求**都走它：

| DataType | 业务 |
|---|---|
| `272,207,42,271,228,13,...` + DateTime=8192 | **分时图**（指数/个股）|
| `10,85,130,6` | 盘口快照 |
| `10,6,66,1111` | 行情摘要 |
| `331124,331125,...` | L2 扩展字段 |
| `92,19,90` | 板块指数分时 |

涉及的代码：1A0001/399001/399006/1B0680（指数）、600000/510980/000001（个股）、883300（板块）。

而代码里的 `9354`（普通分时）/ `9355`（K线/历史分时）可能是**旧版客户端或不同账号等级的 pageid**，当前普通账号已迁移到 4341。

## 现有代码的影响

| 功能 | 当前 pageid | 应改为 | 状态 |
|---|---|---|---|
| `client.timeline`（当日分时）| 9354 | **4341** | ❌ 超时（pageid 错）|
| `client.history_timeline`（历史分时）| 9355 | 待确认（4341?）| ✅ 仍工作（241 条）|
| `client.kline`（K线）| 9355 | 待确认 | 待测 |
| `client.depth_quote`（五档）| 1333 | 待确认 | 待测 |

**历史分时（9355）仍工作**——说明 9355 还有效，可能历史分时走不同路径，或 9355 是另一套仍支持的旧 pageid。
但**当日分时（9354）已失效**，必须改 4341。

## 4341 分时响应解析

- flag=0x006e（新 flag，现有 parser 只认 0x0042/0x0046/0x0086/0x009e）
- hs=72 fc=18（字段表 18 项，比现有的多）
- 字段：dt16,207,42,15,228,13,41,227,19,40,10,224,23,202,223,22,201,208
- 走 BitRLE 位平面（与现有 timeline 同族）
- 现有 `parse_timeline_response` / `parse_index_timeline_response` 因 flag + 字段表不匹配，解出 0 条
