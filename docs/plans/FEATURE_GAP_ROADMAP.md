# 同花顺 PC 版功能复刻路线图（缺口对照表）

> 对照同花顺 Windows PC 免费版（hexin），盘点 `thspypc` 的实现现状与缺口，
> 作为后续补全的优先级依据。本文档随实现进度更新。
>
> 最近能力盘点：2026-08-07。

## 口径说明

- **目标**：基本复刻**同花顺 PC 免费版**的核心行情功能，不是手机版、不是通达信。
- **大单/资金流口径**：PC 版分时图只有一条「大单金额」曲线（主力净额=主动买额−主动卖额），
  **不分**超大单/大单/中单/小单（那是手机版/通达信的口径）。因此个股层面的资金流
  在 PC 版复刻目标里**已达标**，无需按四档拆分。
- **板块层资金流口径**：PC 版板块列表只有**累计主力净流入**一列（dt250，对应
  `board_quotes()` 的 `main_inflow`），**没有**板块分时资金流曲线。2026-08-03
  按 PC 版实际口径收口：板块资金流=该列可用，随 `board_quotes` 已实现。

#### 2026-08-01 第二轮：板块指数活网通过，成分股业务响应待解

**专用板块通道 = fu4.123ths.com 市场组**（2026-08-01 抓包铁证）：**板块指数**
行情/分时/竞价必须走 fu4 服务器（``MarketCode=96;128;88;216;48;``、subreal
通道 URS/UCT/UNX/UCX/UME），**不能在 MAIN/ifindhq 连接上重放**——MAIN 上
原样重放引导帧服务器只回 CodeListSize=0。L2/普通账号 pcap 的板块通道 IP

**成分股独立连接例外**：改走股票行情网关 main/shlv2/szlv2（2026-08-01 晚
根因修复，见下方“成分股空列表根因定位并修复”）。

已落地：

- `LoginIdentity.BOARD`：板块通道 login 壳按账号 profile 分支——Level2 无
  UserName/Password（suffix=计算 check+09，抓包 ``aa 09``）；普通账号
  ``UserName=__manual``（``\r\n\n`` 分隔，suffix 固定 ``5e 07``）。

  分类表 → StockNameVer（L2 双子帧 / 普通 upstockname）。subreal、分类表、
  普通 StockNameVer 与抓包**逐字节一致**（离线回归 `tests/test_board_channel.py`）。
- `resolve_fu4_hosts()`：从 passport M_hqdns 解析 fu4 组 IP（与 MAIN/shlv2

**活网验证结论（2026-08-01 修正，指数接口已打通）**：真实 hexin 客户端在同一账号/设备上始终
可以打开板块行情，因此“多次请求超时导致账号/设备级会话拒绝”不成立；周末也
不能解释同机客户端与 thspypc 的差异。故障最终定位在 thspypc 自身的 fu4
登录拓扑、引导帧和响应读取：

- 双账号 MAIN 行情正常（如 `timeline("000938")` 仍 241 点）——账号未全局受限。
- fu4 对某些登录壳返回 VerifyCode=0，只能证明 login 帧被接受，不能证明该
  socket 已绑定板块业务角色。真实抓包中的 BOARD 壳才是唯一基准，不应降级为
  STANDARD/MANUAL 后继续发送板块引导。
- 旧实现 login 后发送引导时，服务器零响应或 FIN；这个现象现已由缺失帧间
  `0x0a`、错误突发时序和不匹配的 ConfigVer 解释，不是会话拒绝。
- 2026-08-01 再审 pcap 发现实现并未逐项复刻：旧 `_send_board_bootstrap`
  在 login 后立即把引导一次性突发，且漏掉 qureal-init 后的二次 subreal/pageid
  注册；真实客户端分三阶段发送，阶段间约 0.2--0.6 秒。现已按 pcap 分阶段。
- 更关键的误差来自旧分析工具：按 `fdfdfdfd` 切帧时丢掉了帧间字节，因而误判
  “fu4 帧后不能有换行”。原始 TCP 流确认 login、全部引导帧和业务查询后均有
  `0x0a`；无分隔符的旧实现会在阶段 1 后被 FIN。现已统一恢复尾随 `0x0a`。
- 旧引导还把全部 `StockLinkVer/ConfigVer` 伪造成 `0`，并非“逐字节一致”；仓库
  既有 manual-init 调查已记录全零版本会触发错误帧 + FIN。现从本机客户端
  `system/同花顺方案/StockLink.ini` 读取每个 section 的真实版本（与 pcap 一致）。
- board 的 IP 轮换旧实现只改进程内 offset、没有在尝试后写盘；每次新进程运行
  verify 都会重新集中打同一批最快 fu4 节点。现与 MAIN/L2 一样持久化轮换。
- 真实客户端同时建立的多条 fu4/8901 连接分属不同角色。指数 BOARD 每个角色只
  顺序登录一个 IP；成分股另有独立连接：普通账号/Level2 沪侧用 STANDARD
  ``thsuser`` 身份，Level2 深侧用 MANUAL ``__manual``，而 Level2 指数 BOARD
  使用无用户名身份。旧实现把它们合并为一个 BOARD socket，正好解释“指数三项
  正常、成分股静默”。现已新增 ``BOARD_CONSTITUENT_SH/SZ`` 两个连接角色。
- 8/1 verify 出现 fu4 login 全 `-1` 只记录为节点/票据层面的波动，不能推导为
  账号状态恶化；真实客户端同时正常是反证。修复后普通账号活网实测：板块行情
  3 条、历史分时 242 点、2026-07-23 竞价 21 tick 全部通过。
- 16:37/16:40 冷启动干净包澄清了业务模型：普通账号在 Sort 响应边界后才知道
  当前 22 个代码，再发送 527527+行情；抓包中的三次动作是切换板块，均为
  ``SortBegin=0``，不是成分页。Level2 不按可见页分批，而把完整 universe 按市场
  分到两条连接；半导体首批实收沪侧 144+深侧 39。一帧可含多张 ``hd3.1`` 表，
  解析器现会扫描后续表，不再漏掉沪侧 144 条。
- 旧单 BOARD socket 在线验证中，双账号均表现为指数行情/历史分时/目标日竞价通过、
