# 成分股空列表故障复盘（2026-08-01）

> 目的：把这次从“板块指数三接口通过、成分股 ~47s 空列表”到“双账号 176 条 /
> 4--5s”的排查过程固化成经验，避免下次在 8901 协议调试里重复踩坑。

## 结论速览

- **症状**：普通账号与 Level2 的 MAIN 登录、板块行情/分时/竞价全部通过，只有
  独立成分股连接等约 47--48s 后返回空列表。
- **直接机制**：成分股 socket 连到了错误的服务器后端（fu4 板块指数网关
  `globalthsindex-gateway`），服务器对 socket 上的**全部 subreal 注册回
  ``errorcode=-1``**，业务查询只回一个 26B 的空 Sort 响应。
- **根因**：连接目标后端选错 + 引导字节差异 + L2 能力门禁，三个问题叠在一起，
  且前两个问题互相掩盖。
- **修复后**：普通账号走 `main.123ths.com`、L2 沪走 `shlv2.123ths.com`、L2 深走
  `szlv2.123ths.com`，半导体 881121 双账号均返回 **176 条，约 4--5s**。

## 为什么之前会卡住：五个关键教训

### 1. “登录成功” ≠ “通道角色已绑定”

``VerifyCode=0`` 只证明 login 壳被服务器接受，不证明该 socket 已绑定了目标业务
角色（板块指数 / 成分股 / 股票行情）。roadmap 里早就写过这句话，但排查时仍多次
把“login 通过”当作“通道就绪”，直到逐帧转储看到 subreal 全部 -1 才真正落实。

> 教训：**登录通过只值得一个 `login_ok` 标记；通道是否可用必须由引导阶段的
> 逐帧服务端响应（errorcode / CodeListSize / 配置帧）来确认。**

### 2. 一个“必须走 X 服务器”的结论被无边界地推广

抓包确认板块指数必须走 fu4（在 MAIN 上重放只回 CodeListSize=0），于是把
“板块行情/分时/竞价/成分股必须走 fu4”整体写进 roadmap。实际上成分股是例外：
passport 的 `M_hqdns` 字段**已经按市场组分好了域名**——

| 市场组 | 域名 | 市场码 | 对应的成分股连接 |
|--------|------|--------|------------------|
| 沪深基础行情 | `main.123ths.com` | 16;32;144 | 普通账号成分股 |
| 沪 L2 | `shlv2.123ths.com` | 16;144 | L2 沪成分股 |
| 深 L2 | `szlv2.123ths.com` | 32 | L2 深成分股 |
| 板块指数 | `fu4.123ths.com` | 96;128;88;216;48 | 板块指数三接口 |

抓包流对端 IP 与这些域名解析结果一一对应（218.245.102.0 / 122.9.115.201 /
8.134.101.39），但一直没人做“抓包流 IP ↔ passport 域名 ↔ 登录回执”三方核对，
导致成分股连接长期错误地连到 fu4 网关。

> 教训：**“必须走 X 服务器”必须写明适用范围（哪些角色/请求/账号），推广到新的
> 连接角色前，先用对端 IP 与 passport 域名交叉验证。**

### 3. 缺少逐帧收发转储，决定性信号看不到

此前只有请求/响应样本和按 MAGIC 切帧的分析工具，看不到服务器对**每一帧**的
即时响应。而本次的破案信号恰恰是逐帧可见的：成分股 socket 上每个 subreal 注册
都回 `errorcode=-1`（对比：正常板块通道只有 UNS/UHI 回 -1，其余静默接受；抓包
成分股流没有任何 subreal 错误响应）。旧工具按 MAGIC 切帧还会丢帧间 `0x0a`，
曾产生过“帧后无换行”的错误结论。

> 教训：**协议排障先建逐帧收发转储（现已落地 `THS_FRAME_DUMP_DIR`），服务端
> 显式错误码（errorcode / CodeListSize / VerifyCode）优先于字节 diff。**

### 4. 字节对照丢掉了“对端维度”

早期离线对照把“我们与抓包客户端在**不同服务器**上产生的帧差异”直接当作病因。
字节差异里只有一部分是真问题（MKT_INIT 市场集、subreal class、L2 引导结构），
主因在服务器侧：连错后端后，即使逐字节复刻抓包引导帧，服务器依然不回数据。
同一账号、同一后端、同一引导字节，是“逐字节对照成立”的三个前提。

> 教训：**比对两个会话的字节前，先确认对端后端一致（登录回执的 S-Name /
> S-Version 是后端指纹）；否则差异归因没有意义。**

### 5. “空列表 / 超时返回”掩盖了未执行的路径

L2 流程在 SH 批次等待把整体 45s 预算耗尽后 `break`，SZ 批次从未执行，因此表现
为“空列表”而不是“能力异常”。修好 SH 后 SZ 才暴露出第二个独立问题：能力门禁
`L2_MARKET_ACCESS` 证据在 fresh 进程里是 UNKNOWN，深市成分连接被
`UnsupportedAccountFeatureError` 挡住。

> 教训：**“返回空”不等于“走通了只是没数据”。要确认每一步真的执行了（能力
> 门禁、deadline break、accept 过滤都可能吞掉错误）。**

## 排查时间线

| 阶段 | 结论 | 对错 |
|------|------|------|
| fu4 login 全 `-1` | 账号/设备级会话拒绝 | 错：同 IP 短时重复 login 的会话冲突 |
| 修复后指数通过、成分股空 | 账号限流 / 权限问题 | 错：双账号 MAIN 行情正常 |
| 冷启动干净包 | 连接身份/引导角色不匹配 | 对，但只对了一半 |
| 双账号复验（48s 空） | 剩余故障在 bootstrap / 业务字节 / 响应筛选 | 方向对，仍缺对端维度 |
| 活网逐帧转储 | subreal 全部 `errorcode=-1` | 决定性信号 |
| 登录回执 + 对端 IP 对照 | 成分股连错网关（fu4 vs main/shlv2/szlv2） | 真根因 |
| host 组 + 引导字节修复 | 普通账号 176 条通过；L2 暴露能力门禁 | 修复 |
| L2 能力门禁修复 | 双账号四接口全部通过 | 收尾 |

## 避免再犯的 SOP（新通道空响应排查顺序）

1. **核对对端**：抓包流 server IP ↔ passport `M_hqdns` 域名 ↔ 域名 DNS 解析；
   记录登录回执的 `S-Name` / `S-Version` 作为后端身份指纹。
2. **看逐帧服务端响应**：开启 `THS_FRAME_DUMP_DIR`，先找显式错误码
   （`errorcode` / `CodeListSize` / `VerifyCode` / 26B 空响应），再谈字节差异。
3. **确认每个分支真的执行**：能力门禁、超时预算耗尽（deadline break）、
   accept 过滤都会把“失败”伪装成“空”。必要时打日志确认路径。
4. **字节对照三要素**：同一后端、同一账号类型、同一版本环境（如
   StockLink.ini 版本表）；login 掩码对比时保留服务器身份维度。
5. **离线 builder 对照用扁平化嵌套请求序列**，避免 outer 帧打包差异干扰归因。
6. **环境基线**：抓包时客户端版本表（StockLink.ini）、后端 S-Version、日期都要
   记录，版本号差异（如 ConfigVer）不要误判为协议差异。
