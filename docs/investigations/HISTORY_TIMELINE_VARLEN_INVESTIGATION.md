# 个股历史分时变长帧调查

> 状态：外层压缩和完整锚点型个股帧已接入；强状态省略型仍待完整 codec。
> 最近验证：2026-07-28。

## 已有语料

- `captures_live/timeline_20260724_090145.pcap`
- `captures_live/timeline_20260724_091133.pcap`
- `captures_live/timeline_20260724_092405.pcap`
- 同名 `*_resp_stream*.bin` 重组响应流

这些语料包含深市 000938 与指数 399002/1A0002 的 pageid=4417 历史分时请求，
不需要重新抓包即可继续离线分析。

## 已确认的三层结构

### 8901 外层压缩

原始帧以 `cmd=0x0a` 开头时，`hd1.0` 后的所谓“畸形头”只是压缩流中保留下来的
字面量，并非可直接解析的内层表。`normalize_8901_response`（移植自 hexin.exe
RVA `0xf74260`）可把 36-42KB 原始帧正规化为约 44KB 的客户端分发数据。

例如：

```text
36,917B cmd=0x0a → 44,264B → dc=242, flag=0x007e, hs=88, fc=22
41,842B cmd=0x0a → 44,263B → 同上
```

### 指数子表

正规头：

```text
hd1.0\0
dc=0x040000f2
flag=0x007e
hs=88
fc=22
```

字段表和每条记录均为固定宽度。`dc` 低位的 242 还包含壳/尾记录，真实交易日
序列是 241 点，bar 偏移固定为：

```text
0..29, 34..93, 98..128, 227..285, 290..349, 354
```

### 个股子表

同一混合响应里，000938 不是共用指数表，而是嵌套了第二个子表：

```text
dc=0x040000f2
flag=0x0082
hs=92
fc=23
```

逻辑字段比指数多 `dt54`：

```text
dt1/10/13/19/22/23/54/201-204/207-210/223-230
```

完整锚点型中，前六个字段的物理位置稳定，记录尾部因状态字节而常见 89-92B。
解析器用 241 点 bar 序列定位行首，不按经验长度硬切，可安全返回
`bar_index/dt10/dt13/dt19/dt22/dt23`。

强状态省略型还会省略 bar 中高位和后半字段表字节。例如 bar 的
`8a f2 e6 07` 可能只保留成 `8a f2`，后接控制状态。该型目前严格拒绝；实验探针
可以重请求以收集更多变体，但这不是生产正确性方案，不能把错位字节伪装成合法行情。

### 日期编码 off-by-one 修正

2026-07-28 将混合查询中的 `32(399002,)` 替换为 `33(000001,)` 后，响应中的
000001 首末价量额与 thsdk 次日数据吻合。回查旧包又确认：

- `bar_start=132477534` 的 399002 全量对应 thsdk `2026-05-14`；
- 原实现却把该 bar 反算成 `2026-05-13`。

因此 epoch 应为 `ordinal=675064`（1849-04-06），不是原先记录的 675063。
修正后的锚点为：

```text
2026-05-13 → 132475486
2026-05-14 → 132477534
2026-06-30 → 132573790
2026-07-23 → 132620894
```

### 伴随代码替换实验

在同一条已完成 `__manual + init(32)` 的 szlv2 连接上，把抓包请求中的两处
`32(399002,)` 等长替换为 `33(000001,)`，服务端返回两个
`flag=0x0082 / hs=92 / fc=23` 个股子表。第一张明确标记为 000001：

- `bar_start=132479582` 的一次响应恢复 232 个锚点，对 thsdk
  `2026-05-15`：成交额 232/232、成交量 231/232、价格 226/232；
- 修正日期 epoch 后以 `date=2026-05-14` 重发，`bar_start=132477534`，
  首点 `11.14 / 381,200 / 4,246,568` 与 thsdk 同日精确一致；
- 该次强省略变体恢复 225 个锚点，成交额/成交量/价格分别精确
  224/224/218 点；
- 少量价量差异属于尚未完成的状态省略恢复，不影响代码身份判断。

这证明 399002 不是历史分时查询的硬编码依赖，`CodeList` 可以携带其他股票；
它在 PC 客户端请求中主要承担大盘对照伴随序列。

## 已完成验证

完整锚点型的核心字段：

- 2026-05-13：首点 `30.60 / 1,115,400 / 34,131,240`，末点
  `32.91 / 237,260,140 / 7,568,339,900`，与 thsdk 精确一致；服务端该帧缺一个
  bar，返回 240 个可验证点。
- 2026-05-14：241 点，首末价量额均与 thsdk 精确一致。
- 指数 1A0002：241 点 bar 序列与固定跳号位置全部验证。
