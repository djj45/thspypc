# 同花顺协议逆向方法论与实战复盘

> 创建日期：2026-07-28
> 适用范围：同花顺 Windows 客户端的网络协议、二进制数据格式、压缩算法和字段语义逆向
> 性质：可复用的方法论，不代替具体功能的交接文档和地址清单

## 1. 这次逆向真正学到的东西

沪市竞价最终能走通，不是因为某一次“猜中了字节含义”，而是因为逐步建立了三个
互相独立的真值层：

```text
原生算法真值
  Unicorn 执行 hexin 原函数，得到逐字节输出

协议结构真值
  固定头、字段表、记录数、行宽、时间戳链等结构约束

业务数据真值
  thsdk 返回同一股票、同一交易日的价、量、买方未匹配、卖方未匹配
```

最终移植只有同时满足三层才算成功：

1. Python 外层正规化输出与 x86 原函数逐字节一致；
2. 正规化结果满足 CHQuote 固定头和记录结构；
3. 最终字段与独立 thsdk 通道的业务数据一致。

这比“看起来像”“记录数差不多”“某只股票价格能对上”可靠得多。

本次最重要的通用结论：

- 先判断数据处于哪一层，再解释字节；
- 同一业务结果可能有多种物理编码；
- 变体独有字节不一定是噪声，常常正是状态；
- 原生函数的逐字节输出是算法移植的最佳 oracle；
- SDK 可以作为业务真值，但不能默认与客户端使用同一协议；
- 反调试严格时，优先快照、静态分析和离线仿真；
- 任何启发式都必须有明确适用边界和退出条件。

## 2. 先画分层图，禁止跨层猜字段

开始分析前，先把完整数据链写出来：

```text
TCP 字节流
  → 帧头/长度/cmd
  → 外层压缩或打包
  → 业务容器
  → CHQuote 固定头/字段表
  → 记录区压缩
  → 字段值编码
  → 业务语义
```

每发现一个规律，必须注明它属于哪一层。例如：

| 现象 | 所属层 |
|---|---|
| `fdfdfdfd + 8 位 ASCII hex` | TCP 帧边界 |
| `cmd=0x0a + BE32 输出长度` | 外层正规化 |
| `hd1.0`、记录数、行宽、字段数 | CHQuote 容器 |
| BitRLE、位平面转置 | 内层记录压缩 |
| ths_float、varint、哨兵 | 字段值编码 |
| dt27=买方未匹配、dt33=卖方未匹配 | 当前接口的业务语义 |

### 2.1 跨层分析最常见的错误

本次早期看到：

```text
hd1.0 b5 b4 3a 91 14 ...
hd1.M0 b5 a4 3a 14 ...
hd1.0 9b b5 49 3a ...
```

如果直接把这些字节当作 CHQuote 固定头，就会得到不可能的记录数、行宽和字段数。
真实原因是：它们仍处于 `cmd=0x0a` 外层压缩流中，尚未正规化。

因此遇到“字段头随机”“同一字段宽度变化”“时间戳散布”时，第一反应不应是增加更多
字段启发式，而应先问：

```text
我看到的是业务数据，还是压缩后的偶然字面量？
```

## 3. 语料设计比单次抓包重要

### 3.1 最小有效语料矩阵

协议逆向至少需要四个维度：

| 维度 | 目的 |
|---|---|
| 同股同日重复抓取 | 暴露随机物理变体 |
| 多支股票 | 区分控制字节和业务值 |
| 同日独立 oracle | 避免跨日、复权、时钟差异 |
| 不同运行状态 | 区分盘中、盘后历史、缓存和推送路径 |

只抓“一支股票一次”几乎一定会过拟合。

### 3.2 原始字节必须完整保存

保存内容应包括：

- 完整帧体，不只保存从 `hd1.` 开始的切片；
- 抓取时间、股票、市场、请求日期、重复序号；
- 原始长度和 SHA-256；
- 登录/线路/服务器信息，但不得写入账号密码；
- 对应 thsdk oracle 文件；
- 解析器版本或 Git commit。

文件名建议：

```text
auction_raw_<code>_<YYYYMMDD_HHMMSS>_r<N>.bin
_thsdk_auction_<market><code>_<timestamp>.json
```

### 3.3 先按哈希去重，再分析变体

重复抓 8 次不等于 8 个变体。正确流程：

1. 对完整响应计算 SHA-256；
2. 按哈希分组；
3. 记录每个唯一版本出现次数；
4. 对每个唯一版本分别跑解析和 oracle；
5. 文本字段（如 `ServerCost`）差异与业务编码差异分开统计。

这样可以区分：

- 服务器随机选择的编码族；
- 文本长度或耗时字段造成的表面差异；
- 真正随业务数据变化的内容。

### 3.4 跨协议 oracle 只能对业务，不能对字节

thsdk 与 hexin 的竞价协议不是同一套实现。正确用法是：

```text
thsdk：提供同一撮合事件的业务真值
hexin：提供当前要破解的网络字节
```

错误用法是反编译 thsdk，然后假定能得到 hexin 的解码算法。

## 4. 假设必须可证伪

每个猜测都写成：

```text
假设：
如果成立，所有样本必须出现什么？
用哪个最小实验可以推翻？
结果：
结论：保留 / 缩小 / 推翻
```

例如：

### 4.1 “沪市固定每 3 秒一个 tick”

最小证伪实验：

- 读取 thsdk 同日全量时间戳；
- 统计相邻时间差；
- 不先过滤、不补点。

结果出现 2、4 秒及更长间隔，假设被推翻。生产中的 `ts % 3` 只能标记为旧降噪
启发式，不能写成协议事实。

### 4.2 “变体独有字节是随机垃圾”

最小证伪实验：

- 对同股多变体做精确 LCS；
- 只保留公共骨架；
- 检查能否恢复全部时间戳和字段值。

公共骨架只能恢复部分记录，说明独有字节携带压缩状态。LCS 是结构观察工具，不是
解码器。

### 4.3 “内层 BitRLE 就是缺失算法”

最小证伪实验：

- 枚举原始流多个 offset；
- 分别按直接位平面转置和 BitRLE+转置执行；
- 用已知时间戳列评分。

全部零命中后，应停止调内层参数，转向寻找外层正规化。

## 5. 静态逆向的标准顺序

### 5.1 固定二进制版本

每次分析首先记录：

```text
文件路径
文件版本
产品版本
文件大小
SHA-256
PE32 / PE32+
首选 image base
实际加载 base
```

地址文档必须区分：

```text
VA  = 静态虚拟地址
RVA = VA - image base
运行时地址 = module runtime base + RVA
```

本次曾把 `0x167c8b0` 写成 RVA；实际它是 image base 为 `0x400000` 时的 VA，
正确 RVA 是 `0x127c8b0`。这种错误足以让所有 Hook 和断点失效。

### 5.2 从稳定语义锚点进入

推荐搜索顺序：

1. 版本字符串和协议标记：`hd1.`、`hd3.`、服务名；
2. MSVC RTTI 类名；
3. Complete Object Locator 和虚表；
4. 构造函数中写虚表的位置；
5. 虚函数调用点；
6. 输入缓冲区和长度的来源；
7. 返回地址和上游分发链。

本次 `CHQuoteFile` 就是通过：

```text
RTTI 名称
  → 主虚表
  → 构造函数写虚表
  → vtable + 0x14
  → parse 调用点
```

逐步确认，而不是只凭某个函数“看起来像解析器”。

### 5.3 数据流要双向追

从解析器向上追，可以找到输入从哪里来；从 socket/cmd 分发向下追，可以找到哪个
函数实际改写数据。两条链必须在同一个缓冲区边界汇合。

本次只从 `CHQuoteFile` 向上追时，一度怀疑 hlib 请求链负责正规化。完整反向切片后
发现 hlib 只是剥掉自己的 11 字节传输头并原样复制 payload，因此该路线被排除。

真正突破来自另一端：

```text
收集 fdfdfdfd 帧
  → 读取 cmd=0x0a
  → RVA 0xf74260
  → 0x1600 分发
  → 固定 hd1.0
```

### 5.4 只反汇编需要的范围

对几十 MB 的加载映像做整文件反汇编会产生数百 MB 输出，搜索慢且容易混入数据区
伪指令。推荐：

- 用 `pefile` 做节、导入、RTTI 和绝对引用扫描；
- 用小工具寻找直接 call/jmp；
- 用 `objdump --start-address/--stop-address` 看局部；
- 函数确认后再扩大到调用者；
- 大输出放临时目录，不提交仓库。

仓库现有辅助工具：

- `tests/reverse_pe_rtti.py`
- `tests/reverse_pe_callers.py`
- `tests/reverse_pe_string_xrefs.py`
- `tests/reverse_hlib_memory.py`
- `tests/reverse_hexin_minidump.py`

## 6. 保护壳环境下，磁盘文件不等于运行代码

新版本 `hlib.dll` 使用 VMProtect，磁盘 PE 的关键节可能出现：

```text
VirtualSize > 0
SizeOfRawData = 0
```

这时：

- `objdump` 磁盘文件看不到真实代码；
- 文件 RVA 仍可能有效，但对应字节只在加载后出现；
- 静态工具报告“全零”不代表函数不存在。

正确处理：

1. 在正常运行状态生成用户态 minidump；
2. 解析 ModuleList、Memory64List/MemoryList；
3. 按运行时模块 base 重建加载映像；
4. 将地址换算成 RVA；
5. 在重建映像上做 RTTI、虚表和反汇编。

本次通过任务管理器 DMP 得到完整 `hexin.exe` 加载映像，没有附加调试器，也无需
在主程序中注入代码。

### 6.1 DMP 不是天然完整

必须验证：

- 目标模块的整个 `SizeOfImage` 是否被内存段覆盖；
- 目标 RVA 是否落在已捕获页面；
- 页面内容是否是代码而非零填充；
- DMP 模块 base 与静态 image base 的差值；
- 重建文件的空洞范围。

不要因为能找到一段字符串，就假定整个模块已完整提取。

## 7. 动态手段的安全梯度

同花顺存在反调试和反注入风险，默认按以下顺序升级：

```text
1. 网络抓包/原始响应保存
2. 磁盘 PE 静态分析
3. 正常进程 minidump
4. 加载映像静态分析
5. Unicorn 离线仿真纯函数
6. 自有 x86 Harness 中调试 DLL
7. 隔离环境最小化 live Hook
8. 主进程复杂动态跟踪（最后手段）
```

选择原则：

- 前一层能回答问题，就不升级；
- 不在常用账号上验证反调试；
- 不为了“看看会不会被检测”而附加；
- Frida agent 能在普通进程加载，不等于能安全附加 `hexin.exe`；
- 硬件断点、调试器和注入都要视为可能被检测。

## 8. 用 Unicorn 把“看汇编”升级为原生 oracle

如果目标函数：

- 输入输出明确；
- 不依赖复杂对象；
- 外部调用很少；
- 主要是纯计算；

优先把它放进 Unicorn，而不是立即人工翻译。

本次外层正规化函数只需要替换：

```text
malloc
free
memcpy
```

仿真步骤：

1. 映射重建的加载映像；
2. 映射输入、输出指针槽、堆和栈；
3. 构造 x86 调用栈；
4. 对少量外部函数地址加 hook；
5. 执行到返回哨兵；
6. 校验返回长度和输出地址；
7. 保存原生输出 SHA-256。

这样得到的不是“猜测的伪代码”，而是目标版本原函数的真实输出。

### 8.1 原生仿真的验收

- 多个物理变体均可执行；
- 返回长度等于输入声明的 BE32 长度；
- 输出地址位于受控堆；
- 没有未映射读写；
- 同输入重复执行输出一致；
- 输出满足后续固定头结构。

### 8.2 Python 移植必须逐字节对照

推荐顺序：

```text
人工最小分支样本
  → 字面量路径
  → 短匹配
  → 长匹配
  → 字典引用
  → 边界和非法长度
  → 全量真实抓包
```

每个真实样本都比较：

```text
Python output == Unicorn/native output
```

业务字段一致但正规化字节不同，仍说明移植不完全。

## 9. 协议解析必须“先正规化，后严格验收”

生产解析链建议分为：

```text
detect
  → normalize
  → validate container
  → decode records
  → validate semantics
  → narrow fallback
```

### 9.1 正规化入口的安全要求

- 只对明确的命令字节或帧特征启用；
- 输出长度设置硬上限；
- 检查输入至少包含声明长度；
- 所有位流读取做 EOF 检查；
- 字典引用禁止越过已输出区；
- 普通未压缩帧原样返回；
- 失败抛出明确异常，不静默返回半截数据。

### 9.2 固定头结构验收

至少检查：

- 合法版本前缀；
- 记录数合理；
- 头长不越界；
- 行宽和字段数非零且有上限；
- 字段表长度与字段数一致；
- 字段宽度总和与行宽一致；
- 数据区预算合理；
- 记录时间戳合法且单调。

### 9.3 恢复变长记录要有强锚点

600276 旧样本出现 19 字节物理短行，不能据此推广“所有行尾都补零”。当前窄恢复
之所以可接受，是因为同时满足：

- 直接 LE32 时间戳锚点；
- 同交易日；
- 严格递增；
- 锚点数量等于记录数；
- 物理长度只小幅偏离逻辑行宽；
- 补齐后字段宽度和时间戳全部通过；
- 状态尾字节只接受已观察集合。

没有这些约束时应返回失败，不做猜测恢复。

## 10. 字段编号不等于全局业务语义

同一个 dt 号会在不同接口复用：

| dt | 竞价接口 | 其他接口示例 |
|---|---|---|
| dt27 | 买方未匹配委托量 | 含义可能不同 |
| dt33 | 卖方未匹配委托量 | 分时成交额、列表注册制日期等 |

因此字段语义必须绑定：

```text
接口/pageid + 版本 + 字段表 + 数据验证
```

不能看到 dt33 就在全项目中统一解释成“成交额”。

### 10.1 哨兵不能等同于数值零

`0x80000000` 和 `0xffffffff` 在竞价未匹配字段中表示“无值”。底层通用数值解码可能
把其中一些解成 `0.0`，但业务层必须保留区别：

```text
哨兵 → None
真 0  → 0.0
```

正确修复位置是当前接口的字段语义层，而不是修改被十几个接口共用的底层
`decode_ths_float()`。

## 11. 跨通道时间戳不要机械要求完全相等

hexin 8901 与 thsdk/hq.dll 是独立行情分发通道。同一撮合事件可能出现 ±1~2 秒落点
差异。

验证应同时输出：

- 严格时间戳命中；
- 小窗口最近邻命中；
- 窗口内价、量和买卖未匹配是否一致；
- 无法匹配的首尾记录。

窗口匹配不能用来掩盖解析错误。只有当：

- 时间偏差很小；
- 业务值完全一致；
- 偏差在多个样本中表现为通道落点差异；

才可以判为跨通道时钟差异。

## 12. 失败路线也要形成资产

失败实验应记录：

```text
尝试了什么
输入样本
参数范围
评分方式
结果
排除了什么
是否值得再次尝试
```

本次有价值的失败包括：

| 路线 | 为什么失败 | 留下的结论 |
|---|---|---|
| 固定 3 秒扫描 | 真实节拍不固定 | 时间不能作为唯一分帧规则 |
| LCS 删除独有字节 | 独有字节含状态 | LCS 只用于暴露骨架 |
| 原始流直接进 BitRLE | 零时间戳命中 | 缺失层位于 BitRLE 之前 |
| 把随机字节解释成字段宽度 | 不同变体位置旋转 | 仍处在外层压缩流 |
| 反编译 thsdk 找算法 | 协议独立 | thsdk 只做业务 oracle |
| hlib 请求链找正规化 | payload 原样复制 | 目标链在 hexin 8901 |
| 磁盘 hlib 全文件反汇编 | 保护节无原始数据 | 必须分析加载映像 |
| 直接 Frida 主进程 | 反调试风险未验证 | 动态注入降为最后手段 |

失败路线写清楚，可以防止后续任务重新花几小时重复证明同一件事。

## 13. 工具应该声明自己的证据等级

每个逆向脚本的模块注释应明确它属于哪类：

- **capture**：忠实保存原始字节；
- **diagnostic**：输出结构或对齐，不是解码器；
- **oracle**：提供预期输出；
- **emulator**：执行原生目标函数；
- **decoder**：独立实现算法；
- **verifier**：批量比较，不修改数据；
- **production**：面向真实调用，必须严格边界检查。

例如 `reverse_auction_bitstuff.py` 必须明确 LCS 独有字节不能删除；否则后续使用者很
容易把诊断输出误当成正式算法。

## 14. 版本升级后的重新定位流程

同花顺更新后不要直接套旧 RVA。标准流程：

1. 计算新文件 SHA-256、版本、大小；
2. 判断磁盘代码是否仍可见；
3. 需要时重新生成 DMP 和加载映像；
4. 通过 RTTI/字符串/调用特征重新定位；
5. 对旧函数保存语义签名，而不仅是字节签名；
6. 用同一批输入跑旧/新原生函数；
7. 比较输出是否逐字节相同；
8. 只有验证后才更新地址表。

语义签名示例：

```text
输入以 BE32 输出长度开始
三个参数 cdecl
返回 EAX=输出长度
第三参数写输出指针
只调用 malloc/free/memcpy
输出进入 0x1600 分发
```

这种签名比“函数在 RVA 0xf74260”更能跨版本复用。

## 15. 生产代码落地纪律

### 15.1 先加回归器，再改解析器

顺序应是：

1. 保存失败语料；
2. 写能稳定复现失败的测试；
3. 写离线 verifier；
4. 实现正规化/解析；
5. 跑所有唯一变体；
6. 跑其他市场和接口回归；
7. 最后接入生产入口。

### 15.2 启发式必须窄且可观测

若暂时保留 fallback：

- docstring 明确“非完整协议解码”；
- 日志能判断是否命中 fallback；
- 不吞掉正规化异常；
- 不把漏报包装成完整结果；
- 有明确删除条件。

### 15.3 不让 oracle 进入生产依赖

thsdk JSON、DMP、Unicorn 和加载映像只用于开发验证。生产库应只包含：

- 已移植算法；
- 必要结构检查；
- 明确错误处理。

## 16. 文件和安全卫生

不要提交：

- DMP；
- 加载后的完整 exe/dll 映像；
- 真实账号、密码、Passport64、Cookie；
- 大型 pcap 和临时反汇编；
- 编译产物；
- 崩溃转储。

可以提交：

- 逆向脚本；
- Harness 源码；
- 小型合成测试向量；
- 哈希和版本元数据；
- 不含凭据的最小原始样本（确认仓库策略后）；
- 失败实验结论。

路径应通过 CLI 参数传入，不要把个人安装路径作为算法依赖。文档可以记录本机路径，
代码必须允许覆盖。

## 17. 推荐的单次工作循环

每一轮只解决一个可验证问题：

```text
1. 写问题
2. 选最小样本
3. 写可证伪假设
4. 设计正负控制
5. 静态定位或离线执行
6. 保存机器可读结果
7. 与 native/structure/business oracle 比较
8. 更新结论和被推翻内容
9. 加回归测试
10. 再进入下一层
```

不要在一次实验里同时猜：

- 帧边界；
- 压缩算法；
- 字段宽度；
- 数值编码；
- 业务语义。

一次只固定一层，其余层使用已知真值。

## 18. Go / No-Go 检查清单

### 开始解释字段前

```text
[ ] 已确认 TCP 帧边界
[ ] 已确认命令字节
[ ] 已判断是否还有外层压缩
[ ] 固定头字段在当前字节流中自洽
[ ] 同股重复抓包已按哈希去重
```

### 声称算法已破解前

```text
[ ] 有原生函数或另一独立实现作 byte oracle
[ ] 多种物理变体逐字节通过
[ ] 输出长度和边界严格校验
[ ] 没有依赖单支股票常量
[ ] 畸形输入不会越界或超大分配
```

### 声称业务字段已确定前

```text
[ ] 多股票
[ ] 同交易日
[ ] 独立业务 oracle
[ ] 哨兵与真零分开
[ ] 跨通道时间差单独统计
[ ] 字段语义绑定具体接口
```

### 接入生产前

```text
[ ] 离线语料全量通过
[ ] 在线链路至少一轮通过
[ ] 其他市场/历史帧回归通过
[ ] fallback 有清晰边界
[ ] 文档中的旧结论已标记被推翻
```

## 20. 最后一句经验

逆向协议最危险的不是“看不懂汇编”，而是过早给偶然字节赋予业务含义。

可靠的路线始终是：

```text
先确定层级
  → 再获得原生输出
  → 再建立结构约束
  → 最后解释业务语义
```

只要每一层都有独立 oracle，复杂的随机变体、保护壳和状态压缩最终都会从“猜谜”
变成可回归的工程问题。
